# NOTAS — Propuesta superadora (borrador interno)

## Idea pendiente por revisar después: módulo como capa complementaria

- El usuario puede querer crear un módulo que aporte una capa agentica extra con skills propias para su flujo.
- Ese módulo no modificaría el circuito base ni el código central.
- Modificaría el comportamiento en el recorrido del usuario/tarea, en un punto determinado.
- Imagen de referencia: circuito de carreras + atajo en la propia pista, sin reescribir el circuito original.
- El usuario no debería tener que saber de “hooks”, inversión de código ni puntos técnicos de enganche.
- Estado actual: idea en pausa. Volveremos cuando tengamos la base más definida.

## Lo que sí vale la pena afirmar ya

- Separar bien funcionamiento base vs comportamiento complementario.
- Que el módulo no sea “parche del núcleo”, sino una capa propia que se engancha en el flujo.
- Que el usuario hable en intención, no en técnica.
- Que haya un punto claro donde el sistema decide cuando usar lo que el módulo aporta.
- Que el módulo no pueda cambiar el circuito base para todos.
